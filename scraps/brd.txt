Executive Summary
Purpose
The purpose of this Business Requirement document (BRD) is to define the functional requirements for the GeoVision– Enterprise AI Enablement project. This document provides a comprehensive description of the business requirements, functional capabilities, user interactions, system behaviors, and integration requirements for incorporating Artificial Intelligence (AI) into the GeoVision Platform.
The BRD serves as the primary reference for business stakeholders, solution architects, developers, testers, and project teams throughout the solution lifecycle. It establishes a common understanding of the expected system functionality and provides the basis for solution design, development, testing, deployment, and user acceptance.
Project Scope
The GeoVision project aims to enhance the existing Smart Maps Platform with enterprise AI capabilities that enable users to interact with authoritative geospatial data using natural language.
The project includes the implementation of an AI-powered interface that allows users to perform intelligent map searches, discover spatial datasets, execute AI-assisted spatial analysis and receive location-based results through conversational interactions.
The solution introduces an AI Gateway API to securely integrate the GeoVision application with the approved Large Language Model (LLM) platform, Core42 Compass AI. The AI layer will interpret user queries and coordinate with existing GIS services, Feature Services, and the Spatial Database to retrieve validated spatial information and generate meaningful responses.
Key Components Include:
Integration of AI capabilities into the existing Smart Maps Platform. 
Natural language-based search and interaction with spatial datasets. 
AI-assisted spatial analysis and contextual recommendations. 
Discovery of GIS layers and datasets through natural language queries. 
Automated generation of insights, and analytical reports. 
Secure integration with Core42 Compass AI through the AI Gateway API. 
Support for bilingual interactions (Arabic and English). 
Role-based Access Control (RBAC) to ensure users can access only the application features, datasets, and AI capabilities authorized for their roles.
Logging, monitoring, and auditing of AI interactions in accordance with enterprise governance requirements.
Functional Expectations:
The GeoVision Platform aims to provide an AI-enabled geospatial ecosystem where users can access, explore, analyze, and understand government spatial information through conversational interactions while ensuring that all GIS operations continue to be executed using authoritative enterprise GIS services. The solution combines the reasoning capabilities of modern AI with the reliability and governance of Abu Dhabi's Spatial Data Infrastructure, creating a secure, scalable, and future-ready platform for digital government.
The Enterprise AI-enabled GeoVision Platform shall provide the following core capabilities:
Functional Module 1 – AI Enablement:
The GeoVision Enterprise AI Enablement solution extends the existing Smart Maps Platform with Artificial Intelligence (AI) and Natural Language Processing (NLP) capabilities to provide a more intelligent, user-friendly, and scalable geospatial experience.
The implementation of AI Enablement provides the following business benefits:
Improved User Experience: Simplifies access to spatial information through conversational interactions, reducing the learning curve for non-GIS users. 
Enhanced Decision-Making: Delivers AI-generated insights, and recommendations to support informed planning and operational decisions. 
Operational Efficiency: Accelerates data discovery and spatial analysis by reducing the number of manual steps required to retrieve and visualize information. 
Governance and Security: Ensures that all AI interactions comply with government security standards through role-based access control, audit logging, and secure integration with authoritative GIS services. 
Future Scalability: Provides a flexible architecture capable of supporting additional datasets, AI capabilities, themes, and digital government services without major redesign.
Functional Module 2 – Conversational Map Interface:
The Conversational Map Interface enables users to interact with the Platform using natural language instead of traditional GIS tools. 
Users can submit queries in English or Arabic, and the system interprets their intent, executes the corresponding GIS operations, and returns results in an intuitive format such as text, tables, maps, charts, or reports (if applicable). Enable users to discover relevant datasets, map themes, and spatial layers using natural language queries. Support context-aware conversations, allowing users to ask follow-up questions while maintaining the context of previous interactions.
The conversational interface is designed for both GIS and non-GIS users, making spatial information accessible without requiring technical GIS expertise.
The system shall:
Accept English and Arabic prompts. 
Identify user intent. 
Maintain conversation context. 
Interpret follow-up questions. 
Execute GIS queries. 
Display map results. 
Recommend related datasets. 
Generate Map only reports 
Functional Module 3 – Smart Filtering and Map Visualization:
The Smart Filtering & Map Visualization module enables users to interactively visualize and analyze spatial data based on natural language queries. Once the AI interprets the user's intent, the Smart Maps backend applies the appropriate attribute and spatial filters to the selected datasets and dynamically updates the map.
The Smart Filtering & Map Visualization module includes:
Intelligent map filtering based on AI interpretation 
Attribute-based filtering and Spatial filtering 
Feature highlighting 
Dynamic map updates 
Thematic visualization 
Automatic zoom to selected features 
Real-time rendering of filtered results 
Active filter management 
Integration with GIS Services and Feature Services
Functional Module 4 – Sketch based AI Insights & Export:
The Sketch-based AI Insights & Export module enables users to perform interactive spatial analysis by drawing an Area of Interest (AOI) directly on the Smart Maps interface. Users can sketch freehand or use predefined geometric shapes to define the analysis area. Once the AOI is submitted, the system performs spatial intersection analysis against the enabled Smart Maps layers, identifies relevant features, and generates AI-assisted insights and recommendations.
This module includes:
Interactive sketch tools 
Area of Interest (AOI) selection and spatial intersection analysis
Feature counting and categorization 
Pattern detection and Analytical visualizations 
Map-only export 
Integration with Smart Maps layers and GIS services
Functional Module 5 – Bilingual Support:
The Bilingual Support module enables the platform to provide a seamless user experience in both English and Arabic. The solution supports bilingual interaction throughout the complete user journey, AI interpretation, GIS processing, map visualization, reports, and AI-generated responses.
The platform leverages Core42 Compass AI to process natural language queries in either language while maintaining the same functional capabilities regardless of the selected language. Users may choose their preferred language at login or switch languages during an active session. 
This module includes:
English and Arabic query input and responses
Localized user interface labels 
Bilingual reports and charts (if applicable)
Government-standard Arabic terminology 
Language switching 
Integration with Core42 Compass AI for multilingual processing 
Functional Module 6 – Secure Deployment and API Security:
The Secure Deployment and API Security module defines the security considerations for integrating the Enterprise AI Platform with the GeoVision application and backend services. The module focuses on protecting communications between the AI components, the AI Gateway, and the GIS backend while ensuring compliance with DGE IT governance and cybersecurity policies.
This module includes:
Secure API communication between the AI Gateway and backend services 
AI Gateway security architecture 
API authentication and authorization mechanisms (subject to DGE security requirements) 
Secure integration with GIS services and Feature Services 
Audit logging and monitoring of AI service interactions 
Secure deployment within DGE-approved infrastructure 
Compliance with DGE IT governance and cybersecurity policies 
Encryption of data in transit and other applicable security controls
Functional Module 7 – Compass AI Integration:
The Compass AI Integration module enables natural language understanding and conversational intelligence within the Enterprise AI Platform. Core42 Compass AI serves as the AI reasoning layer that interprets user requests, identifies user intent, extracts relevant entities, and generates structured function calls for execution by the Smart Maps GIS backend.
Compass AI does not directly access spatial datasets or GIS services. Instead, it provides structured instructions that are executed by the Smart Maps backend through approved APIs and ArcGIS Feature Services, ensuring that authoritative GIS processing remains within the secure GIS environment.
The Compass AI Integration module includes:
Natural Language Query (NLQ) processing. 
Text-based conversational interactions. 
Context-aware conversations within the active session. 
Support for follow-up questions based on previous user interactions. 
Map-based search using natural language. 
Spatial intent interpretation to identify geographic entities, locations, and spatial relationships. 
Feature service queries through secure backend function calls. 
Map filtering through backend integration. 
Structured chart and graph responses (if applicable).
Compass AI acts solely as the reasoning layer and does not directly execute GIS queries or access spatial datasets.

Enhanced (Smart Maps Phase 1 + GeoVision)
Description
The system shall provide Smart Filters that enable users to refine and narrow search results, datasets, and map features based on selected spatial and attribute criteria. Users shall be able to apply one or more filters simultaneously, including category, location, distance, and other supported filter parameters. The map and search results shall update dynamically based on the applied filters, allowing users to efficiently identify relevant spatial information.
Functional Area
Smart Filters 
User Persona
Guest User, Registered Public User
Acceptance Criteria
Users can apply one or more Smart Filters to refine map results and datasets.
The system dynamically updates the map and search results based on the selected filters.
Users can modify or remove applied filters without restarting the search.
Users can clear all applied filters and restore the default search results.
Multiple filters can be applied simultaneously where supported.
Non-Functional Requirements:
The GeoVision Enterprise AI Platform shall satisfy the following non-functional requirements to ensure the solution is secure, reliable, scalable, performant, and compliant with the Department of Government Enablement (DGE) standards. These requirements define the quality attributes and operational constraints that the solution must meet in addition to its functional capabilities.
Performance Requirements
The solution shall be designed to meet enterprise-level performance targets under normal operating conditions. Performance benchmarks will be validated during System Integration Testing (SIT), User Acceptance Testing (UAT), and Performance Testing.
Performance Considerations:
Actual performance may vary depending on:
Infrastructure sizing 
Volume of spatial datasets 
GIS service response time 
AI model processing time 
Network latency 
DGE-approved deployment architecture 
Performance testing shall be conducted using representative production workloads to validate compliance with the above targets.

Major enhancements requested after requirements sign-off that are outside the agreed project scope. 
Infrastructure upgrades or procurement outside the agreed implementation scope.

Glossary and Definitions
Term
Definition
AI Assistant
The conversational interface within GeoVision that enables users to interact with the system using natural language and receive AI-generated responses, recommendations, and insights.
AI Gateway
The secure integration layer that connects GeoVision with the approved enterprise AI platform for processing natural language requests while maintaining secure communication with backend services.
Area of Interest (AOI)
A user-defined geographic area created through sketching or selection to focus map visualization, filtering, or spatial analysis.
Basemap
The background map that provides geographic context for displaying operational GIS layers and spatial information.
Buffer
A spatial analysis function that creates a specified distance around a selected location or feature to identify nearby spatial data.
Category
A thematic grouping of related spatial datasets, such as Education, Healthcare, Tourism, or Environment.
Cluster
A visual grouping of multiple map features displayed together at lower zoom levels to improve map readability and performance.
Dataset
A collection of related geospatial information published for visualization, analysis, or reporting within GeoVision.
Feature
An individual spatial object represented on the map, such as a school, hospital, road, or landmark.
Interactive Map Workspace
The primary working area where users visualize, navigate, search, and analyse geospatial information using interactive map tools and AI capabilities.
Natural Language Query (NLQ)
A capability that enables users to search and interact with GeoVision using conversational English or Arabic instead of structured GIS queries.
Point of Interest (POI)
A specific geographic location or landmark that users can search for, view, or analyse within the application.
Search History
A record of previously executed search queries that enables users to quickly revisit or repeat earlier searches.
Spatial Analysis
The process of analysing geographic data to identify relationships, patterns, proximity, or trends within a defined geographic area.
Spatial Data
Information that represents the location, shape, and attributes of geographic features.
Theme
A logical grouping of datasets representing a specific business domain, such as Education, Healthcare, Utilities, or Tourism.
AI Insight
An AI-generated summary, recommendation, or analytical observation produced from user queries and spatial datasets.
Context-Aware Conversation
An AI capability that retains the context of previous interactions to support follow-up questions and continuous conversations.
Prompt
A natural language question or instruction entered by the user to interact with the AI Assistant.
